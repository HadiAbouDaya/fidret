# Task title

- Status: planned
- Human owner: Unassigned
- Agent or harness: Unassigned
- Branch: Unassigned
- Updated: YYYY-MM-DD
- Verification status: not-run

## Purpose

Describe the requested outcome and how it serves Fidret's purpose. Link relevant company context or decisions.

## Scope

Define deliverables, affected areas, dependencies, and overlap with other tasks. Record who integrates any agreed overlapping work.

## Execution boundaries

- Authorized scope: record the request and applicable standing authorization; identify any external action outside that scope without asking again for authorization already given.
- Worktree: record the task branch/worktree using a portable name; inspect Git to locate the actual checkout.
- Dependencies: link prerequisite tasks or decisions and state any unresolved input.
- Coordination: name each editing agent's owned files and the integration owner; use separate worktrees for parallel editing.

## Plan

List the meaningful implementation steps. For a small task, one clear step is sufficient.

## Acceptance criteria

State observable conditions that establish the task is complete.

## Decisions

Link durable decision records. Label unanswered choices and assumptions.

## Verification

Record exact commands or review steps, their results, and any checks not performed.

Set top-level `Verification status` to `not-run`, `partial` or `passed`. A done task requires `passed`; preserve exact evidence and limits here.

## Handoff

- Checkpoint: describe what is implemented and its current state.
- Remaining work: list unfinished acceptance criteria, or state none when complete.
- Next action: give the next concrete step; put a follow-up in a new task when appropriate.
- Blockers: identify the missing input or external condition, or none.
- Acceptance basis: record actual acceptance or the applicable request/standing authorization; do not infer another person's review.
- Publication: distinguish local changes, commits, push, PR, merge and verified deployment with identifiers; state what has not been done.
- Last verified: record the date, relevant ref/commit or check evidence and any unverified external state.

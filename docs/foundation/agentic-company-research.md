# Harness engineering and company readiness: source ledger

Research checked 29 October 2026 in Europe/Paris (initial retrieval on 28 October UTC). This supports the [article task](../tasks/2026-10-29-agentic-company-post.md) and [canonical piece](../../lab/pieces/agentic-company-harness.md). The public article's five contracts are an original synthesis, not a named external standard. Primary sources were opened, not taken only from search snippets. Full temporary source copies stay in ignored local research files; the repository retains links and concise findings.

| Primary source | Publication/status | Useful evidence and scope |
| --- | --- | --- |
| [LangChain company harness](https://www.langchain.com/blog/components-building-company-harness) | 24 Oct 2026 | Internal implementation report connecting workplace interface, identity, memory, execution and recurring tasks. A timely vendor case, not a universal architecture. |
| [OpenAI Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform) | 19 Aug 2026 | Reusable harness surfaces alongside application-owned context and controls. Product integration choices, not a company security certification. |
| [Anthropic Managed Agents](https://www.anthropic.com/research/managed-agents) | 8 Apr 2026 | Durable session, harness and execution separation; credential proxy/vault. Model-specific context-reset scaffolding changed across models. |
| [Anthropic containment](https://www.anthropic.com/research/how-we-contain-claude) | 25 May 2026 | Environment boundaries complement model defenses; trusted connectors can carry untrusted content. Product-specific report, not proof of universal containment. |
| [OpenAI sandbox security](https://developers.openai.com/api/docs/guides/agents-api/environments/security) | Living documentation | Isolation, outbound restrictions and credentials outside generated-code execution. A broker must still constrain operations; hiding secrets alone does not establish business intent. |
| [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) and [security practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices) | 2026-07-28 specification | Scopes, audience validation, token handling and confused-deputy risks. HTTP authorization and STDIO differ; protocol access is distinct from transaction approval. |
| [NIST identity discussion](https://www.nist.gov/blogs/cybersecurity-insights/back-future-why-agentic-ai-needs-strong-identity-foundation) | 27 Aug 2026 | Accountable delegation and agent identity connect to established IAM problems. Explanatory guidance. |
| [NIST identity project update](https://www.nist.gov/news-events/news/2026/09/comments-software-and-agentic-ai-identity-concept-paper) | 29 Sep 2026 | Comments and intended practical demonstrations. Emerging work, not a completed enterprise identity standard. |
| [OWASP Agentic Top 10 for 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) | 9 Dec 2025; 2026 edition | Risk taxonomy including goal/context/privilege failures. The edition year is not the publication year. |
| [OWASP Agent Control Standard](https://genai.owasp.org/resource/agent-control-standard-acs/) | 1 Sep 2026 | Project work on runtime controls. Landing page inspected; no conformance implementation or certification claimed. |
| [OWASP red-teaming manual v1.0](https://genai.owasp.org/resource/genai-red-teaming-manual-version-1-0/) | 20 Oct 2026 | Scoped testing, reproducibility and regression work. Coverage supports bounded findings, not elimination of all attacks. |
| [Harness-aware plugin evaluation](https://developers.openai.com/cookbook/examples/partners/harness_aware_plugin_evals/harness_aware_plugin_evals) | 23 Sep 2026 | Distinguishes direct tool tests, a controlled model loop and product-harness behavior. Specific plugin/corpus results are not imported into Fidret claims. |
| [OpenAI improvement loop](https://developers.openai.com/cookbook/examples/agents_sdk/agent_improvement_loop) | 12 May 2026 | Traces and feedback can become evals and reviewed changes. A worked example, not evidence that this process has secured Fidret. |
| [Anthropic long-running application harness](https://www.anthropic.com/research/harness-design-long-running-apps) | 24 Mar 2026 | Verification and evaluator behavior require engineering. Additional agents carry costs and can miss errors. |

Independent source review found no material security overclaim in the draft. It prompted more precise OAuth wording and readable mobile diagram access. The illustrative contract binding approval to actor/target/payload/version/expiry remains a proposal to implement and test. Unknown outcomes require reconciliation before retry; some recovery needs compensation or a human. Logs need redaction, access control and retention. No real API/model calls, company penetration test or physical trial was run for this article.

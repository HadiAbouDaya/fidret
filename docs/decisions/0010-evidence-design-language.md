# An evidence-led design language for Fidret

- Status: active
- Date: 2026-10-28
- Human decision owner: Hadi Abou Daya
- Related task: [Website design revamp](../tasks/2026-10-28-design-revamp.md)
- Basis: Implementation convention within Hadi's explicit full-redesign request, including research, adapted design guidance and useful new website experiences

## Context

The initial site is a deliberately small company introduction. Hadi now requests a complete design revamp, research into a design skill that avoids generic generated output, a durable visual language and distinctive useful additions. Fidret's purpose remains Trust earned; Physical AI remains a developing practice. The public site has no verified commercial delivery history to turn into a gallery of case studies.

## Decision

Use **A working field of evidence** as the website's visual direction: substantial Manrope typography, asymmetric open compositions, forest/ivory/sage surfaces, restrained meaningful copper events and original sensing/observation diagrams. Preserve the licensed font assets and the company name/tagline. Replace the first brief's composition defaults with the [v2 canonical language](../design/fidret-design-brief.md); historical v1 remains available in Git.

Adapt Impeccable's critique and surface-oriented design ideas, complemented by the installed frontend-design skill, into an original [Fidret project skill](../../skills/fidret-design/SKILL.md). Record [research and provenance](../design/research.md). Do not install upstream launchers, hooks or concept-selection machinery. The skill does not create an additional approval policy or grant publication authority.

Carry the visual system through the company pages, Lab reading surfaces and 404. Add a native-control walkthrough grounded in the existing synthetic sensor-freshness prototype, with explicit assumptions, limitations and sources. Preserve static Astro/TypeScript, same-origin assets, zero browser JavaScript, existing content/byline rules, strict response policies and Free hosting.

## Consequences

Future agents can recover visual intent from the repository and distinguish company presentation, technical reading and experiment interaction. The memorable experience is tied to actual software evidence instead of invented projects. Original artwork and native controls still require rendered review, readable mobile fallbacks, contrast and keyboard checks. The skill's presence does not prove every harness discovers it, an external detector passed or the design is deployed.

Design evolution should update the canonical brief and relevant implementation together. Changes to runtime architecture, public claims or hardware scope retain their existing decision and authorization boundaries.

## Alternatives considered

- Importing an upstream skill unchanged would add installation and approval machinery unrelated to the delegated task and duplicate existing context.
- Cosmetic polishing would not meet the requested complete redesign.
- A generic technology landing page, fabricated project gallery or simulated live dashboard would weaken the company's evidence standard.
- Replacing the entire palette and font set is unnecessary: composition, original explanatory work and interaction provide enough scope for a distinct new result.

# Default AI-DLC for website work

- Status: active
- Date: 2026-11-06
- Human decision owner: Hadi Abou Daya
- Related task: [Default AI-DLC website workflow](../tasks/2026-11-06-aidlc-adoption.md)
- Basis: Hadi explicitly requested permanent automatic AI-DLC adoption across all website work on 6 November 2026; local integration convention within that request

## Context

Fidret already has shared instructions, tasks, decisions and checked PR delivery. Hadi wants [AWS Labs AI-DLC](https://github.com/awslabs/aidlc-workflows) applied without repeatedly naming it. Upstream v2.11.3 is a five-phase, 33-stage method with a native runtime and per-stage fresh-human gates. Installing every harness projection would introduce competing state, hook trust and settings changes, and repeated approvals inconsistent with existing authorized continuation.

## Decision

Make the [Fidret AI-DLC skill](../../skills/fidret-aidlc/SKILL.md) mandatory by default from canonical AGENTS.md for website work. Pin byte-exact upstream stage/profile/phase and selected verification/recovery guidance, with provenance, hashes and MIT-0 license. Apply the lifecycle through the existing repository records and checks using the explicit [local translations](../collaboration/aidlc.md).

New substantive tasks declare profile, depth, all-stage dispositions and rationale, authority, operation status and acceptance-to-implementation-to-verification traceability. Keep thin adapters for supported harnesses. Existing historical records stay truthful; resuming substantive work adds lifecycle evidence rather than rewriting history. Local foundation validation protects the automatic entry path and record/inventory contracts.

Use current requests and existing standing authority for ordinary execution and checked PR merges. No fresh approval or engine audit event may be fabricated. New material decisions or external actions still need their applicable authority. Company purpose, website architecture and existing design/search standards remain governed by their canonical records.

## Consequences

Website work follows a documented adaptive lifecycle by default, with offline source guidance and inspectable continuity. Contributors maintain stage/traceability evidence proportionate to the work. Structural checks cannot prove actual instruction loading, semantic sufficiency or a human decision.

This is methodology adoption, not native engine installation or a claim of passing upstream runtime conformance. There is no provider/model switch, global installation, hook/permission change, new website runtime or extra cloud service. The pinned method can evolve only through reviewed repository changes.

## Alternatives considered

- Native installation across all harnesses: supplies deterministic engine/hooks but changes many project settings and creates independent state and human-presence gates. Defer until explicitly needed and compatible with the authorized workflow.
- An instruction to use a remote guide: small, but depends on network/latest content and cannot enforce locally inspectable evidence.
- Rename existing task headings only: misses adaptive stage selection and element-level traceability. Add those explicit contracts instead.

Revisit the adaptation when a concrete task shows that native runtime capabilities are needed.
